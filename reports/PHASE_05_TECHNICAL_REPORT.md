## Implemented

- Migration `007_local_prefill.sql` adds private visited cities, source/model/config-bound suggestions, owner decisions and before/after snapshots, and undoable bulk location receipts. A migration test exercises schema 6 to 7 without losing rows.
- CPU ONNX Runtime runs a quantized CLIP model on verified stored thumbnails. Before classification, the service rehashes the original or managed copy and thumbnail against catalog SHA-256 values. The model sees the thumbnail, never the original. Labels cover broad content and conditions; relative similarity gaps leave uncertain subject/description blank. Evidence includes top matches, luminance measurements, filename and EXIF hints, GPS match status/distance, model ID/revision/settings, source hash, and timestamp. No exact landmark is inferred.
- `config/local_model.json` pins model ID, immutable revision, MIT license as listed on the [model card](https://huggingface.co/Xenova/clip-vit-base-patch32), each file SHA-256, and ignored cache path. The quantized ONNX weight is 153,695,702 bytes; tokenizer and config files add about 2.23 MB. First local use fetches missing files via HTTPS and validates checksums before promoting them from `.partial` to cached files. The UI polls download progress and shows failures. Offline mode checks only the cache. `scripts/setup_env.py --prefetch-model` automates offline preparation.
- `requirements.in` adds direct pins for NumPy 2.5.4, ONNX Runtime 1.31.1, and tokenizers 0.23.3. The full `requirements.lock` pins 32 resolved packages. Setup installs/verifies the same locked environment in repository `.venv`; no alternate virtual environment was created. The Windows Python 3.13.5 environment and one local inference on a synthetic 256 px image passed. Linux Python 3.13 x86-64 wheels for the three direct packages were found/downloaded into ignored test data; ONNX Runtime requires a manylinux glibc 2.28 compatible host. Linux execution is configured in CI but has not run locally.
- Private visited-city CRUD remains server-side; city list responses omit stored coordinates. GPS match requires the closest city to be inside its radius and at least 5 km or 25% closer than a rival eligible city. `NO_GPS`, `UNMATCHED`, and `AMBIGUOUS` propose no city. The UI supports adding, correcting, and removing visited cities; one-photo suggestion review; first-20-visible recognition; selected-field acceptance, dismissal, and undo; bounded prepared-batch acceptance/undo; and preview/apply/undo for first-20-visible city assignment. Existing scalar owner fields remain untouched; new tags append only after acceptance, and unrelated AI-tag provenance remains intact. Changed owner data or city revisions reject stale suggestions. Prompt approval is revoked and compiled prompts marked stale after accepted metadata changes.
- `scripts/phase05_audit.py` backs up an existing SQLite catalog and compares original hashes before and after owner review. The [Phase 05 owner guide](../docs/PHASE_05_REVIEW.md) covers Windows PowerShell and Linux fresh-shell steps, private backup, a 20-photo pilot, automatic model setup, and visual acceptance.
- CI workflow targets the new branch and uses synthetic photos plus a fake recognizer, with no model download or paid endpoint.

## Limitations and owner handoff

CLIP category quality on actual travel photos is unmeasured. The label set is intentionally broad, and similarity is not probability. The owner should record wrong or uncertain suggestions in the 20-photo pilot and adjust labels/thresholds before using a 200-photo run. Prepared-batch acceptance calls the per-photo decision endpoint sequentially; if a later item fails, earlier accepted items remain and the UI offers undo for those successes. Location bulk apply uses a saved revision preview and rejects stale state. Saved visited-city coordinates remain server-side, so a correction requires reentering the complete city record. Server shutdown waits for in-flight edit workers; a stalled provider request can delay exit until that request finishes or times out. Future export must use only editorial location accepted or entered by the owner and must keep precise GPS private. Do not advance to Phase 06 or merge until owner review, tests, report, and pilot findings are accepted.
