## Design and privacy

The existing verified CLIP ONNX model remains under ignored `data/models/`; only candidate labels and the settings version changed. Pending suggestions can help text search, while selected subjects, tags, exact landmarks and locations remain under owner review. CLIP does not generate prose or technical correction instructions.

`prompt_refinement.py` adds a server-side text-only OpenAI Responses boundary using `gpt-6-luna`, `reasoning.effort=none`, 700 maximum output tokens and `store=false`. The adapter reads `OPENAI_API_KEY` only from the process environment. The planning estimate uses a conservative UTF-8 byte-based input-token count plus an output-token allowance and [standard model prices observed 2026-11-04](https://developers.openai.com/api/docs/models/gpt-6-luna); it can differ from actual billing. The alias may change, so the owner must recheck model and pricing before a paid run. The application injects no original or publication image, file path, raw EXIF, precise GPS or source hash into the request. It uses the current deterministic prompt, which may contain owner-entered text and confirmed tags; the owner explicitly authorizes that text request. Raw provider response and request text are private SQLite data.

Each proposal is linked to the exact baseline, source hash and publication profile. Adoption fails if that baseline is stale or if the proposal drops source/derivative rules, owner instructions, profile, allowance, constraints or consent text. Existing conflict checks still apply at adoption and approval. Adoption creates a new immutable pending prompt; only a later explicit prompt approval can make it image-job eligible, and paid image editing still requires its separate authorization. These string checks cannot prove arbitrary prose is semantically faithful; owner comparison is required.

The [original SmolVLM-256M card](https://huggingface.co/HuggingFaceTB/SmolVLM-256M-Instruct) lists Apache-2.0, a 513 MB weights file and under 1 GB GPU RAM for one image. The [GGUF variant](https://huggingface.co/ggml-org/SmolVLM-256M-Instruct-GGUF) lists a 175 MB Q8 file and Windows/Linux llama.cpp commands. Neither source provides verified CPU peak memory, latency or quality on the owner's photographs in this application's canonical environment. Installing a second runtime outside `.venv`, downloading unpinned files or claiming scene-description quality would breach the phase gate. Selection remains open pending a reproducible CPU/package evaluation and pilot.

No Python or frontend package changed. `requirements.in`, `requirements.lock`, `scripts/setup_env.py` and `frontend/package-lock.json` remain as in Priority 2. CI continues to recreate `.venv` from the lockfile on Windows and Linux. Schema 12 is included in the layout migration's accepted range.
